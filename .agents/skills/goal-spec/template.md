# `/goal` command template

Replace every placeholder with discovered facts and approved choices. Keep the prompt pointer-rich: the canonical spec and tickets contain the source requirements; this prompt supplies execution policy and the approved dispatch plan.

```text
/goal Implement every unfinished ticket in SPEC_DIR, integrate the complete change on branch `INTEGRATION_BRANCH`, and finish with a spec-level review handoff. Completion requires every ticket to be done and merged with its acceptance criteria evidenced, every ticket handoff and implementation findings note written, all relevant checks passing, no `INTEGRATION_BRANCH-NN` branches remaining, and `SPEC_DIR/implementation-review-handoff.md` complete. If an unresolved blocker prevents all remaining work, print `BLOCKED: <reason>` after recording the finished work and remaining frontier. Stop after TURN_LIMIT turns; if incomplete then, leave the run state ready to resume.

Primary worktree: PRIMARY. Canonical spec: SPEC_PATH. Tickets and dependencies: TICKET_GRAPH. Run state: STATE_PATH. Ticket handoffs: HANDOFF_DIR/NN.md. Research directory: RESEARCH_DIR. Base branch: BASE_BRANCH at immutable starting SHA START_SHA. Integration branch: INTEGRATION_BRANCH. Build: BUILD_COMMAND. Tests: TEST_COMMANDS. Baseline: BASELINE. Prerequisites and ignored-file setup: PREREQUISITES. Project rules: PROJECT_RULES.

Orchestrator: ORCHESTRATOR_MODEL_AND_REASONING. The orchestrator reads, plans, delegates, monitors, and reviews subagent work; it does not write implementation code or project documents. Approved subagent dispatch plan: PLAN. Global implementation concurrency: LIMIT. Explicit subagent assignments (role, profile, resolved model, reasoning, budget, isolation, and concurrency): ROLE_PLAN. Per-ticket dispatch table: TICKET_PLAN. Workflow overhead and optional subagents: OVERHEAD_AND_OPTIONAL_ROLES. The user chose and approved these subagent assignments during prompt preparation. Use the active sub-agent mechanism and pass each assignment explicitly. Verify assignments remain available before dispatch; if any cannot be honored, stop and report the mismatch without substitution or dispatch. Any change to model, reasoning, concurrency, isolation, budget, or optional roles needs renewed user approval.

Steps:
A. Read SPEC_PATH, every ticket in TICKET_GRAPH, cited research, earlier ticket findings, run state, and relevant handoffs. Verify code pointers against current code and note drift. Compute and record the frontier. A ticket is ready only when unfinished and every blocker is done and recorded as merged. Never dispatch blocked work.
B. First run only: have the approved merger/recorder subagent record START_SHA and run the approved baseline commands at that revision; record their results, including existing failures, in STATE_PATH. Adopt INTEGRATION_BRANCH only if its recorded starting SHA matches, otherwise create it from BASE_BRANCH at START_SHA. Never recreate or rebase INTEGRATION_BRANCH. Confirm the primary worktree is clean before switching branches. Create `INTEGRATION_BRANCH-NN` from the latest integration branch in an isolated worktree for each ready ticket and give that branch to its implementer.
C. Dispatch one isolated implementer subagent for each ready ticket, up to the approved concurrency. Each gets the absolute canonical spec/ticket paths and read-only .specs/.research context. It maps every acceptance criterion to changes and test seams, tests first, implements only its ticket, runs BUILD_COMMAND and relevant TEST_COMMANDS, and returns commits, results, findings, research drift, and unresolved questions. It must not write ticket status, STATE_PATH, handoffs, or .research findings.
D. For each completed ticket, run `/code-review` against its ticket branch's base commit, passing the approved assignments explicitly to the named `review-standards` and `review-spec` reviewers and following the repository's review guidance. Fix findings on the ticket branch, repeat relevant validation, and record each finding and resolution.
E. Integrate tickets serially. If the integration branch moved since a ticket branch started, have the approved merger merge its latest revision into that ticket branch and re-run relevant checks. The merger inspects and integrates the reviewed branch with `--no-ff`, runs relevant checks after merge in the primary worktree, and restores the prior branch. The orchestrator reviews the merge evidence and asks for a bounded subagent fix if needed.
F. After each ticket merge, the approved merger subagent alone writes HANDOFF_DIR/NN.md, STATE_PATH, and RESEARCH_DIR/ticket-NN-implementation-findings.md. Include merge SHA, acceptance evidence, implementation and review results, research drift, later-ticket relevance, what the ticket unblocks, and a `Still unclear or open` list. Serialize these writes; other agents return findings but do not edit shared records. The orchestrator reads and verifies the updates. Read completed findings before dispatching later tickets. On a blocker or turn limit, the merger records current status and the remaining frontier; do not create a findings note without a merge SHA.
G. Repeat from the updated frontier until all tickets are done or no unfinished ticket is ready. Continue independent work when one ticket blocks. Record blockers without marking their tickets done.
H. Run selected optional final red-team review only with its approved assignment. Have the approved merger write SPEC_DIR/implementation-review-handoff.md with every requirement classified complete/partial/missing/ambiguous/unrequested and evidence pointers; separate verified checks from inference; include final revision, plan, confidence, assumptions, risks, findings and remaining gates. The orchestrator reads and verifies it.
I. Have the approved merger/recorder clean completed ticket worktrees and delete their `INTEGRATION_BRANCH-NN` branches; confirm `git branch --list INTEGRATION_BRANCH-NN` is empty. Preserve incomplete ticket branches only when STATE_PATH records how to resume them. Retain INTEGRATION_BRANCH. Never weaken, skip, or delete tests; baseline failures are not regressions. Keep .specs/.research updates local and uncommitted. Do not push, create a pull request, or modify BASE_BRANCH. The orchestrator does not write code or project documents; delegate every edit to the assigned subagent role.

Final report: final revision, checks, ticket coverage, handoff and research paths, approved plan, confidence and remaining gates. If turn-limited, report the exact unfinished frontier and preserve all completed ticket records.
```
